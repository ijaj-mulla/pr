## Replay Mode
Replay mode uses the actual `events.jsonl` file to simulate historical robot events. The replay covers the time window from t=0 to t=900 seconds (15 minutes). It features:
- A shared simulation clock
- Play/pause controls
- Speed controls (0.5x, 1x, 2x, 5x, 10x)
- Timeline seek functionality
- Reset to beginning
- At any simulation time T, each robot displays its latest event where event.t <= T

The replay logic is implemented in `src/App.tsx` using `requestAnimationFrame` for smooth playback, and the fleet state is updated via `updateFleetAtTime` in `src/store/fleetStore.ts`.

## Live Mode
Live mode is a browser-only simulator that generates NEW events continuously rather than replaying the events.jsonl file. This approach:
- Eliminates the need for backend infrastructure
- Simplifies deployment for the challenge scope
- Is limited to the browser session (not a true multi-client/server-connected production feed)

Implementation details:
- Update rate: 1 second (1000ms)
- Generates gradual x/y movement based on robot type (picker: 5 units/sec, hauler: 8 units/sec)
- Generates gradual battery changes (drains when active, increases when charging)
- Generates sensible status transitions using all 8 robot statuses
- Never teleports robots randomly
- Uses the same centralized Zustand fleet-state update path as replay mode
- Properly cleans up timers when switching between Replay and Live modes

The live simulator is implemented in `src/lib/liveSimulator.ts` and feeds events through the same `updateRobotState` function in `src/store/fleetStore.ts`.

## Working/Attention Classification
The dashboard classifies robots into two categories:

**Working:** `active`, `on_mission`
- Robots that are actively performing tasks

**Attention Needed:** `blocked`, `error`, `offline`, `maintenance`
- Robots that require operator intervention

**Not Automatically Attention:** `idle`, `charging`
- These statuses are considered normal states and do not trigger attention alerts

This classification is implemented in `src/lib/fleetUtils.ts` (`isWorking` and `needsAttention` functions) and used in `src/components/FleetSummary.tsx`.

## Fleet Activity Trend
The dashboard displays ONE fleet-level trend chart showing the percentage of active robots over time. The activity is calculated as:

```
(active + on_mission) / total robots
```

This trend is based on actual event data from the replay window (t=0 to t=900) and is computed in `src/lib/fleetUtils.ts` (`calculateFleetActivityOverTime` function). The chart is rendered in `src/components/FleetActivityChart.tsx` using Recharts.

## Supported Robots and Statuses
- **All 8 robots** from the challenge data are supported
- **All 8 statuses** are supported: `idle`, `active`, `on_mission`, `charging`, `blocked`, `error`, `maintenance`, `offline`
